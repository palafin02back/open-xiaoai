## 两种VAD技术对比

### 技术架构对比

| 特性 | WebRTC VAD | Silero VAD |
|------|------------|------------|
| **算法类型** | GMM（高斯混合模型） | DNN（深度神经网络） |
| **模型大小** | 无外部模型，纯C代码 | ~2MB ONNX模型 |
| **处理速度** | <1ms / 30ms帧 | <1ms / 30ms帧 |
| **内存占用** | 极低（<1MB） | 较低（~50-100MB） |
| **依赖项** | 无（纯C实现） | ONNX Runtime |
| **语言支持** | 所有（规则-based） | 6000+语言训练 |
| **许可证** | BSD-3 | MIT |

### 准确率对比（关键数据）

```
准确率对比 (TPR - True Positive Rate，在不同 FPR 下):

┌────────────────────────────────────────────────────────────────────────┐
│ FPR (误报率)    │ WebRTC VAD    │ Silero VAD    │ 差距            │
├────────────────────────────────────────────────────────────────────────┤
│ 5% FPR          │ ~50% TPR      │ ~87.7% TPR    │ Silero胜出37.7% │
│ 1% FPR          │ 极低(不可用)   │ ~80.4% TPR    │ Silero完胜      │
│ 25% FPR         │ ~75% TPR      │ ~93% TPR      │ Silero胜出18%   │
└────────────────────────────────────────────────────────────────────────┘

解读：
- 5% FPR: 每100帧非语音，5帧被误判为语音
- WebRTC 在 5% FPR 下漏检约 50% 的语音帧（每2帧漏1帧）
- Silero 在 5% FPR 下只漏检约 12.3% 的语音帧（每8帧漏1帧）
```

### 噪声环境表现

| 环境 | WebRTC VAD | Silero VAD |
|------|------------|------------|
| **安静室内** | ✅ 表现良好 | ✅ 表现优秀 |
| **轻度噪声** | ⚠️ 可能误判 | ✅ 表现良好 |
| **背景音乐** | ❌ 容易误判 | ✅ 能区分 |
| **多人说话** | ❌ 无法区分 | ⚠️ 有一定能力 |
| **户外/嘈杂** | ❌ 表现差 | ✅ 表现较好 |

### 优缺点总结

**WebRTC VAD:**
```
优点:
✅ 极其轻量，无外部依赖
✅ 纯C实现，易于嵌入任何项目
✅ 处理速度极快
✅ 内存占用极低
✅ 在安静环境下表现足够

缺点:
❌ 噪声环境下准确率低
❌ 容易将非语音误判为语音
❌ 静音检测优于语音检测
❌ 无法区分说话人
```

**Silero VAD:**
```
优点:
✅ 噪声环境下准确率高
✅ 支持6000+语言
✅ 多领域数据训练，泛化能力强
✅ 可选GPU加速
✅ 有Go语言ONNX实现

缺点:
❌ 需要ONNX Runtime依赖
❌ 模型文件~2MB
❌ 内存占用略高
❌ 集成复杂度较高
```

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        智能音箱语音处理架构                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                    第一层：硬件前端处理                           │   │
│  │  ┌─────────┐   ┌──────────────┐   ┌──────────────┐              │   │
│  │  │ 麦克风阵│ → │ 波束成形     │ → │ 回声消除     │              │   │
│  │  │ 列(4-6个)│   │ (Beamforming)│   │ (AEC)        │              │   │

│  │                         ↓                                        │   │

│  │  └──────────────────────────────────────────────┘               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              ↓ (唤醒成功)                               │

│  │  │ 高精度VAD (类似Silero VAD)                    │               │   │
│  │  │ 精确端点检测，确定命令边界                     │               │   │
│  │  └──────────────────────────────────────────────┘               │   │
│  │                         ↓                                        │   │
│  │  ┌──────────────────────────────────────────────┐               │   │
│  │  │ 云端/本地 ASR (语音识别)                      │               │   │
│  │  └──────────────────────────────────────────────┘               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
```

## 多轮对话场景需求

### 场景特点

```
多轮对话流程：

用户: "小爱同学，打开客厅的灯"
音箱: "好的，已为您打开客厅的灯"
       [进入监听模式，等待后续指令]

用户: "再把亮度调到50%"           ← 无需再说唤醒词
音箱: "好的，亮度已调整到50%"
       [继续监听]

用户: "谢谢"
音箱: "不客气"
       [超时退出监听模式]
```

### 核心需求

| 需求 | 重要性 | 说明 |
|------|--------|------|
| **快速响应** | ⭐⭐⭐⭐⭐ | 延迟<200ms，对话流畅 |
| **精准端点检测** | ⭐⭐⭐⭐⭐ | 用户说完立即响应，不能早切 |
| **噪声鲁棒性** | ⭐⭐⭐⭐ | 过滤TV/音乐/环境噪声 |
| **低功耗** | ⭐⭐⭐ | 持续监听不发热 |
| **简单集成** | ⭐⭐⭐ | Go语言，易维护 |

### 挑战分析

```
多轮对话的VAD挑战：

1. 音箱回放干扰
   ┌────────────────────────────────────────────────────────────┐
   │ [用户说话] [音箱回放TTS] [用户继续说] [音箱再次回放]       │
   │                 ↓                                          │
   │           VAD可能被自己的TTS触发                           │
   │                 ↓                                          │
   │           需要回声消除/自消音机制                          │
   └────────────────────────────────────────────────────────────┘

2. 停顿判断
   ┌────────────────────────────────────────────────────────────┐
   │ "打开那个...卧室的...那个灯"                               │
   │            ↑           ↑                                   │
   │         思考停顿      思考停顿                             │
   │           不应该在这里切断                                 │
   └────────────────────────────────────────────────────────────┘

3. 背景干扰
   ┌────────────────────────────────────────────────────────────┐
   │ [用户说话] + [电视背景音] → VAD需要正确区分                │
   └────────────────────────────────────────────────────────────┘
```

## 推荐方案

### 方案对比

| 方案 | WebRTC VAD | Silero VAD | 混合方案 |
|------|------------|------------|----------|
| **准确率** | 中 | 高 | 高 |
| **延迟** | 极低 | 低 | 低 |
| **复杂度** | 低 | 中 | 中高 |
| **资源占用** | 极低 | 中 | 中 |
| **适用场景** | 安静环境 | 各种环境 | 各种环境 |

### 最终推荐：Silero VAD

基于以下考虑，**推荐使用 Silero VAD**：

```
决策因素：

1. 准确率优先
   - 多轮对话中，端点检测错误会严重影响体验
   - Silero 在 5% FPR 下 TPR 达到 87.7%，远超 WebRTC 的 50%
   
2. 噪声环境
   - 智能家居场景经常有背景噪声（电视、音乐、其他人）
   - Silero 的抗噪能力明显更强

3. Go语言支持
   - Silero 有成熟的 Go + ONNX Runtime 实现
   - github.com/streamer45/silero-vad-go
   - github.com/plandem/silero-go

4. 资源可接受
   - 模型 ~2MB，内存 ~50-100MB
   - 处理速度 <1ms/帧，满足实时需求
   - 对于树莓派等边缘设备完全可以承受

5. 多语言支持
   - 训练数据涵盖 6000+ 语言
   - 中文表现优秀
```

### 为什么不选混合方案

```
混合方案（WebRTC粗筛 + Silero精筛）的问题：

1. 复杂度显著增加
   - 需要维护两套VAD代码
   - 状态机设计更复杂
   
2. 收益不明显
   - Silero 已经足够快（<1ms/帧）
   - 额外的粗筛节省的资源有限
   
3. 可能引入新问题
   - WebRTC 误判可能导致漏检
   - 两层之间的协调容易出bug

结论：单独使用 Silero VAD 是最佳性价比选择
```

### Go语言实现要点

```go
// 推荐使用的库
import (
    // 方案1: streamer45/silero-vad-go (CGO + ONNX)
    silero "github.com/streamer45/silero-vad-go"
    
    // 或方案2: plandem/silero-go
    // silero "github.com/plandem/silero-go"
)

// 推荐参数配置
const (
    SampleRate         = 16000    // 16kHz 采样率
    FrameDurationMs    = 30       // 30ms 帧长度（Silero推荐）
    SpeechThreshold    = 0.5      // 语音概率阈值
    MinSpeechFrames    = 3        // 最少3帧确认语音开始（~90ms）
    SilenceTimeoutMs   = 1200     // 1.2s 静音超时（多轮对话适当延长）
    PreBufferFrames    = 10       // 保留300ms预缓冲
)
```

### 多轮对话优化配置

```yaml
# 多轮对话模式配置
multi_turn_config:
  # 语音检测
  speech_threshold: 0.5          # 语音概率阈值
  min_speech_duration_ms: 90     # 最小语音持续时间
  
  # 静音检测（多轮对话需要更长）
  silence_timeout_normal: 1000   # 正常模式静音超时
  silence_timeout_listening: 1500 # 监听模式静音超时（更容忍停顿）
  
  # 预缓冲（避免丢失首字）
  pre_buffer_ms: 300             # 300ms预缓冲
  
  # 多轮对话
  listening_timeout: 5000        # 5秒无语音退出监听模式
  barge_in_enabled: true         # 支持打断音箱回放
```

### 部署依赖


### 降级方案

如果部署环境资源极其有限（如低端嵌入式设备），可考虑降级到 WebRTC VAD：

```go
// 降级条件
if runtime.GOMAXPROCS(-1) < 2 || availableMemoryMB < 50 {
    // 使用 WebRTC VAD 作为降级方案
    vad = webrtcvad.NewVAD()
} else {
    // 使用 Silero VAD
    vad = silero.NewDetector()
}
```
